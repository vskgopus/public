      Module 2 — MCU & Peripherals

      ← Module 1 · Course home · Next: Communication Protocols → · Take the quiz

      Learning goals

      • Configure GPIO pins correctly (input/output, pull-up/down, push-pull/open-drain).
      • Explain how interrupts and the vector table work.
      • Calculate timer periods, PWM duty cycle and ADC results.
      • Choose between polling, interrupts and DMA.
      • Expert: handle cache/DMA coherency, barriers, register races, errata, BIT and timing determinism.

      Register names and formulas differ between MCU families. The examples use STM32-style timers and an ARM Cortex-M core. Always check the reference manual and datasheet for your part.

      Beginner 1. Beginner

      1.1 Memory-mapped I/O

      Peripherals are controlled through registers that sit at fixed addresses in the memory map. Writing to an address configures hardware:

      #define GPIOA_ODR (*(volatile uint32_t *)0x4001080CU)   /* example address only */
GPIOA_ODR |= (1U << 5);

      In real projects, use the vendor's device header (CMSIS) rather than raw addresses.

      1.2 GPIO

      Setting Meaning
      Input / Output Direction of the pin
      Push-pull output Actively drives both high and low
      Open-drain output Can only pull low. Needs a pull-up resistor to go high. Lets several devices share a line (used by I2C).
      Pull-up / pull-down Weak resistor that gives a floating input a defined level

      A push-button wired between the pin and GND needs a pull-up. The pin reads 1 when the button is released and 0 when it is pressed.

      Never leave inputs floating. They pick up noise and can increase power consumption.

      1.3 Button debouncing

      Mechanical contacts bounce for a few milliseconds. To get one clean event, either sample the input periodically (for example every 5–10 ms) and accept a change only after several equal readings, or add an RC filter with a Schmitt-trigger input.

      1.4 Clock

      Every peripheral needs a clock. On most MCUs you must enable the peripheral clock (for example an RCC enable bit) before its registers respond. Forgetting this is one of the most common causes of "my peripheral does nothing".

      Intermediate 2. Intermediate

      2.1 Interrupts

      When an interrupt fires, the CPU saves its context, looks up the handler address in the vector table, runs the ISR, then returns. On Cortex-M the NVIC controls enabling and priorities. A lower priority number means higher urgency.

      Rules for good ISRs:

      • Keep them short. Set a flag, copy data, or give a semaphore, and do the processing elsewhere.
      • Do not block or busy-wait, and avoid printf and malloc.
      • Clear the peripheral's interrupt flag, otherwise the ISR re-enters straight away.
      • Variables shared with main code must be volatile and accessed atomically.

      2.2 Polling vs interrupt vs DMA

      Method CPU load Best for
      Polling High (CPU waits) Very simple or very fast one-off operations
      Interrupt Low to medium Events arriving at unpredictable times
      DMA Very low Moving blocks of data (ADC samples, UART/SPI buffers) without CPU involvement

      2.3 Timers

      For an STM32-style timer:

      f_update = f_timer_clock / ((PSC + 1) × (ARR + 1))

      Example: 72 MHz clock, PSC = 7199, ARR = 9999 → 72 000 000 / 7200 = 10 kHz tick, then 10 000 / 10 000 = 1 Hz update event.

      2.4 PWM

      duty cycle = CCR / (ARR + 1)

      With ARR = 999 and CCR = 250 the duty cycle is 25 %. PWM is used for motor speed, LED dimming and servo control.

      2.5 ADC

      An N-bit ADC has 2ᴺ codes. For a 12-bit ADC with V_REF = 3.3 V:

      1 LSB = 3.3 V / 4096 ≈ 0.806 mV
V_in  = code × V_REF / 4096          (code 2048 ≈ 1.65 V)

      (Some texts divide by 2ᴺ − 1 instead. The difference is below one LSB.)

      Nyquist: sample at more than twice the highest frequency in the signal, and use an anti-aliasing filter in front of the ADC.

      Advanced 3. Advanced

      3.1 Watchdog timer

      A watchdog resets the MCU if the software does not refresh ("kick") it in time. Kick it from one place that only runs when the system is healthy, for example after all tasks have reported in. Never kick it from a timer ISR that keeps running while the main loop is stuck.

      3.2 Brown-out and reset sources

      A brown-out detector (BOD/BOR) holds the MCU in reset while the supply voltage is too low for reliable operation. After a reset, read the reset-cause register (power-on, watchdog, brown-out, software, pin) and log it. It is very useful when debugging field failures.

      3.3 Critical sections and atomicity

      uint32_t primask = __get_PRIMASK();   /* CMSIS intrinsics on Cortex-M */
__disable_irq();
shared_counter++;
__set_PRIMASK(primask);               /* restore previous state */

      Keep critical sections short, because they add to interrupt latency.

      3.4 Low-power modes

      MCUs offer sleep or stop modes that turn off clocks to save energy. They wake on interrupts. Typical pattern: do the work, then __WFI() (wait for interrupt) in the idle loop. Disable unused peripherals and configure unused pins so they don't float.

      3.5 Cortex-M interrupt features

      • Tail-chaining: when one ISR ends and another is pending, the core skips the full context restore and save between them.
      • Nesting: a higher-priority interrupt can pre-empt a running lower-priority ISR.
      • HardFault: usually caused by invalid memory access, an unaligned access where it is not allowed, or a stack overflow. Inspect the stacked PC and the fault status registers.

      Expert 4. Expert: the hardware/software interface in high-integrity systems

      For engineers with 3+ years of experience. Most "impossible" field failures come from this boundary: caches, write buffers, races on registers, silicon errata and timing that only fails under load.

      4.1 Caches and DMA coherency

      On cores with a data cache (for example Arm Cortex-M7), the CPU and a DMA controller can see different contents for the same RAM:

      Direction Problem Typical fix
      CPU → DMA (transmit) Data still sits in the cache, so the DMA sends stale RAM Clean the buffer's cache lines before starting the DMA
      DMA → CPU (receive) The CPU reads old cached data Invalidate the buffer's cache lines after the transfer (and avoid touching the buffer during it)

      Align DMA buffers to the cache-line size (32 bytes on Cortex-M7) and size them as a multiple of it. Otherwise invalidating a line can destroy neighbouring variables. Alternatives are a non-cacheable MPU region for DMA buffers, or tightly coupled memory. CMSIS provides helpers such as SCB_CleanDCache_by_Addr() and SCB_InvalidateDCache_by_Addr(). Confirm them in your device's CMSIS version.

      4.2 Memory barriers on Arm Cortex-M

      Barrier Use it when
      __DMB() Ordering memory accesses, for example before signalling another bus master or core that data is ready
      __DSB() You need earlier memory accesses to be complete, for example after clearing an interrupt flag just before returning, or before __WFI()
      __ISB() After changing system configuration (MPU, VTOR, CONTROL) so that later instructions use the new settings

      A classic symptom: an ISR runs twice for one event. The write that clears the peripheral's flag was still in a write buffer when the exception returned, so the interrupt was still pending. Fixes: read the register back, or use __DSB() before returning, as the vendor recommends.

      4.3 Races on peripheral registers

      GPIOA->ODR |= (1U << 5);   /* read-modify-write: an ISR that writes ODR between the read and
                              the write loses its update */

      Use hardware atomic set/reset registers where they exist (for example BSRR on STM32), exclusive access instructions (LDREX/STREX on Armv7-M and Armv8-M Mainline; not available on Cortex-M0/M0+), or a short critical section.

      4.4 Memory protection unit (MPU)

      • Stack guard: a no-access region at the end of each stack turns a silent overflow into an immediate fault.
      • Partitioning: keep tasks or partitions away from each other's data, and make code regions execute-only or read-only. This is the basis of space partitioning (see Module 4).
      • Null-pointer trap: make address 0 inaccessible where the memory map allows it.

      4.5 Timing determinism and WCET

      Caches, branch predictors, flash wait states with prefetch buffers, and DMA bus contention all make execution time depend on history. They improve average time but make worst-case analysis harder. Options:

      • static WCET analysis tools that model the processor (only for supported cores),
      • measurement-based WCET with stress conditions and a documented margin,
      • reducing variability: cache locking or partitioning, running critical code from tightly coupled memory, and limiting DMA during critical windows.

      On multicore devices, shared buses, caches and memory controllers create interference channels between cores. See Module 4 and Module 5.

      4.6 Silicon errata and documentation discipline

      Every MCU revision has an errata sheet that lists where the silicon doesn't match the datasheet or reference manual, usually with workarounds. In high-integrity projects:

      • record which silicon revision you designed and tested against,
      • review the errata sheet for every peripheral you use, and record how each relevant erratum is handled,
      • re-check when the hardware team moves to a new revision.

      4.7 Built-in test (BIT) and fault detection

      Test Typical method
      Power-up RAM test March algorithms (for example March C−). They detect stuck-at, transition and many coupling faults that simple write/read patterns miss.
      Program memory integrity CRC over flash at start-up, and periodically in the background
      Clock monitoring Clock-security or clock-monitor features, or cross-checking against an independent oscillator
      Watchdog Windowed watchdog: refreshing too early also causes a reset, which catches code that kicks it from a runaway loop
      Memory errors ECC/EDAC RAM with scrubbing: periodically read and correct memory so that single-bit upsets (for example from radiation at altitude) don't build up into uncorrectable multi-bit errors

      Each BIT needs requirements for what it detects, how quickly, and what the system does on failure.

      4.8 Start-up and reset behaviour

      • Initialise ECC RAM before any read of it, often in the start-up code, because reading uninitialised ECC RAM can fault.
      • Decide the safe state of every output from reset until software configures it. That is a hardware/software requirement, not an afterthought.
      • Record the reset cause and keep a small non-volatile fault log for maintenance.
      • Bootloaders and software loading are part of the certified configuration in avionics. Their behaviour after an interrupted update must be specified and verified.

      Key takeaways

      • Enable the clock, configure the pin, then use the peripheral.
      • Keep ISRs short, clear their flags, and protect shared data.
      • Know the timer, PWM and ADC formulas for your MCU, and check them against the reference manual.
      • Use DMA for bulk data and the watchdog for recovery.

      Self-check

      1. A 16 MHz timer clock with PSC = 15. What ARR value gives a 1 kHz update rate?
      2. Why does an I2C line need open-drain outputs?
      3. A 10-bit ADC with a 5 V reference reads 512. What is the approximate input voltage?
