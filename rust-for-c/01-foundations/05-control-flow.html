Rust for C Programmers

Control flow

In C

if (x) { ... } else { ... }                 /* any non-zero value is true */
for (int i = 0; i < n; i++) { ... }
while (cond) { ... }
do { ... } while (cond);
switch (x) { case 1: ...; /* falls through */ case 2: ...; break; default: ...; }
goto cleanup;

In Rust

if

The condition must be a bool. Parentheses are not needed, but braces are required. if is an expression.

fn main() {
    let x = 3;
    if x > 0 {
        println!("positive");
    } else if x < 0 {
        println!("negative");
    } else {
        println!("zero");
    }
}
fn main() {
    let x = 3;
    if x {          // error[E0308]: expected `bool`, found integer
        println!("yes");
    }
}

Loops

Rust has three: loop (infinite), while, and for. There is no C-style three-part for and no do/while.

fn main() {
    // loop: infinite; `break` can carry a value
    let mut tries = 0;
    let found = loop {
        tries += 1;
        if tries == 4 {
            break tries * 10;       // the loop evaluates to 40
        }
    };
    println!("{found}");

    // while
    let mut n = 3;
    while n > 0 {
        n -= 1;
    }

    // do { } while (cond)  ==  loop with a break at the end
    let mut k = 0;
    loop {
        k += 1;
        if k >= 3 { break; }
    }
}

for iterates over an iterator. Ranges are the equivalent of counting loops, and they cannot go out of bounds or off by one into an uninitialized index:

fn main() {
    for i in 0..3 {            // 0, 1, 2   (end excluded)
        print!("{i} ");
    }
    for i in 0..=3 {           // 0, 1, 2, 3 (end included)
        print!("{i} ");
    }
    for i in (0..3).rev() {    // 2, 1, 0
        print!("{i} ");
    }
    for i in (0..10).step_by(4) { // 0, 4, 8
        print!("{i} ");
    }
    println!();

    let a = [10, 20, 30];
    for x in a {               // by value (arrays of Copy types)
        print!("{x} ");
    }
    for (i, x) in a.iter().enumerate() {   // index and element together
        print!("[{i}]={x} ");
    }
    println!();
}

C’s for (i = 0; i <= n; i++) is for i in 0..=n. There is no way to write the classic off-by-one past the end by accident; and iterating the elements directly needs no index at all.

Labels

break and continue can target an outer loop by label, replacing most uses of goto and flag variables:

fn main() {
    'outer: for i in 0..5 {
        for j in 0..5 {
            if i * j == 6 {
                println!("found {i} {j}");
                break 'outer;
            }
        }
    }
}

match: a safer switch

match compares a value against patterns. It has no fall-through (no break needed) and must be exhaustive: the compiler rejects a missing case.

fn describe(n: i32) -> &'static str {
    match n {
        0 => "zero",
        1 | 2 | 3 => "small",          // several values
        4..=9 => "medium",             // a range
        x if x < 0 => "negative",      // a guard
        _ => "large",                  // `_` is `default`
    }
}

fn main() {
    for n in [0, 2, 5, -4, 100] {
        println!("{n}: {}", describe(n));
    }
}

Forget a case and it will not compile:

fn main() {
    let n: u8 = 3;
    let s = match n {
        0 => "zero",
        1 => "one",
        // error[E0004]: non-exhaustive patterns: `2_u8..=u8::MAX` not covered
    };
    println!("{s}");
}

Patterns can also bind parts of the value, which is where match becomes far more powerful than switch (chapters 6 and 14).

if let, while let, let … else

Shorthand when you care about one pattern only:

fn main() {
    let maybe: Option<i32> = Some(7);

    if let Some(v) = maybe {
        println!("got {v}");
    }

    let mut stack = vec![1, 2, 3];
    while let Some(top) = stack.pop() {
        print!("{top} ");
    }
    println!();

    let Some(v) = maybe else {
        return;                  // the else branch must diverge
    };
    println!("{v}");
}

Under the hood

  • A for over a range or a slice compiles to the same loop you would write by hand: the iterator machinery is removed by the optimizer. Iterating a slice also lets the compiler drop bounds checks that an indexed loop might keep.
  • A match on integers becomes a jump table or comparison tree, like switch.
  • Exhaustiveness checking is purely compile time and costs nothing.

C habits to unlearn

  • Do not index arrays in loops when you only need the elements; iterate them.
  • Do not use integers as booleans or pointers as conditions.
  • Do not use fall-through; list several patterns with |.
  • Do not write sentinel and flag variables for nested loops; use labels.

Solutions

1.

fn main() {
    for i in 1..=100 {
        match (i % 3, i % 5) {
            (0, 0) => println!("FizzBuzz"),
            (0, _) => println!("Fizz"),
            (_, 0) => println!("Buzz"),
            _ => println!("{i}"),
        }
    }
}

2. do { body } while (x != 0) runs the body first, then tests. A loop with the test at the bottom does the same:

fn main() {
    let mut x = 3;
    loop {
        println!("{x}");
        x -= 1;
        if x == 0 {
            break;
        }
    }
}

3. Without the _ arm the compiler rejects the match with error[E0004]: non-exhaustive patterns, and names a range of values that no arm covers. A guard such as x if x < 0 does not count towards exhaustiveness, because the compiler cannot reason about arbitrary conditions. C compilers at best warn about a missing default.

4.

fn collatz_steps(mut n: u64) -> u32 {
    let mut steps = 0;
    while n != 1 {
        n = if n % 2 == 0 { n / 2 } else { 3 * n + 1 };
        steps += 1;
    }
    steps
}

fn main() {
    assert_eq!(collatz_steps(1), 0);
    assert_eq!(collatz_steps(6), 8);
    assert_eq!(collatz_steps(27), 111);
    println!("ok");
}

5.

fn grade(score: u32) -> char {
    match score {
        90.. => 'A',
        80..=89 => 'B',
        70..=79 => 'C',
        _ => 'F',
    }
}

fn main() {
    assert_eq!(grade(90), 'A');
    assert_eq!(grade(89), 'B');
    assert_eq!(grade(70), 'C');
    assert_eq!(grade(69), 'F');
    println!("ok");
}

Ranges replace the if/else if ladder, and the compiler checks that every value is covered.
