Rust for C Programmers

Compound types

In C

Aggregates are arrays, struct and union. An array decays to a pointer and loses its length, a union does not remember which member is live, and an enum is just named integers.

struct point { int x, y; };

enum shape_kind { CIRCLE, RECT };
struct shape {
    enum shape_kind kind;          /* the "tag", kept by hand */
    union {
        struct { double r; } circle;
        struct { double w, h; } rect;
    } u;
};

In Rust

Tuples

fn main() {
    let t: (i32, f64, char) = (1, 2.5, 'x');
    println!("{} {} {}", t.0, t.1, t.2);       // fields by position
    let (a, b, c) = t;                          // destructuring
    println!("{a} {b} {c}");
}

Arrays

[T; N] is a fixed-size array value. The length is part of the type. It does not decay to a pointer, and indexing is bounds checked.

fn main() {
    let a = [1, 2, 3, 4, 5];       // [i32; 5]
    let zeros = [0u8; 16];         // 16 zero bytes, like `uint8_t z[16] = {0};`
    println!("{} {}", a.len(), zeros.len());

    let i = std::hint::black_box(7);  // hides the constant, so the check happens at run time
    // a[i] panics at run time: "index out of bounds: the len is 5 but the index is 7"
    // In C this reads past the end: undefined behavior.
    if i < a.len() {
        println!("{}", a[i]);
    }
    println!("{:?}", a.get(i));    // None: a checked access, no panic
}

Slices: pointer plus length

A slice &[T] is a view into part of an array or vector. It is a fat pointer: an address and a length, the pair that C programs pass by hand as (int *a, size_t n).

use std::mem::size_of;

fn sum(xs: &[i32]) -> i32 {        // C: int sum(const int *xs, size_t n)
    let mut total = 0;
    for x in xs {
        total += x;
    }
    total
}

fn main() {
    let a = [1, 2, 3, 4, 5];
    println!("{}", sum(&a));        // whole array
    println!("{}", sum(&a[1..4]));  // elements 1, 2, 3 -> 9
    println!("{}", size_of::<&[i32]>() == 2 * size_of::<usize>()); // true
}

A slice carries its length, so functions cannot walk past the end without the check noticing.

Structs

struct Point {
    x: i32,
    y: i32,
}

struct Meters(f64);      // tuple struct: a named wrapper
struct Marker;           // unit struct: no data

fn main() {
    let mut p = Point { x: 1, y: 2 };
    p.x += 10;
    let q = Point { y: 99, ..p };         // copy remaining fields from p
    println!("{} {} {}", p.x, p.y, q.y);
    let m = Meters(3.5);
    println!("{}", m.0);
    let _ = Marker;
}

There is no designated-initializer shorthand with omitted fields: every field must be given, so there are no uninitialized members.

Enums: tagged unions done right

A Rust enum is a sum type: each variant may carry data, and the compiler tracks which variant is live. This is the struct { tag; union } pattern from C, built in and checked.

enum Shape {
    Circle { r: f64 },
    Rect { w: f64, h: f64 },
    Point,
}

fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle { r } => 3.14159 * *r * *r,
        Shape::Rect { w, h } => w * h,
        Shape::Point => 0.0,
    }
}

fn main() {
    let shapes = [Shape::Circle { r: 1.0 }, Shape::Rect { w: 2.0, h: 3.0 }, Shape::Point];
    for s in &shapes {
        println!("{}", area(s));
    }
}

You cannot read the wrong union member: the only way to the data is match, which also forces you to handle every variant. Adding a variant makes every non-exhaustive match fail to compile.

Plain C-like enums are available too, with explicit values:

#[derive(Debug, Clone, Copy)]
enum Color {
    Red = 1,
    Green = 2,
    Blue = 4,
}

fn main() {
    println!("{} {:?}", Color::Blue as i32, Color::Green);   // 4 Green
}

Unlike C, Color is its own type: an arbitrary integer is not a Color.

impl: functions attached to a type

struct Counter {
    n: u32,
}

impl Counter {
    fn new() -> Counter {            // associated function: Counter::new()
        Counter { n: 0 }
    }
    fn bump(&mut self) {             // method: takes the struct "by pointer"
        self.n += 1;
    }
    fn get(&self) -> u32 {           // read-only method
        self.n
    }
}

fn main() {
    let mut c = Counter::new();
    c.bump();
    c.bump();
    println!("{}", c.get());         // 2
}

This is the C convention counter_new(), counter_bump(struct counter *c), with the naming and the pointer argument built into the language. Chapter 13 covers it fully.

Binding by reference with ref

Matching on a value moves non-Copy data out of it. Putting ref in front of a binding borrows that part instead, so the original stays usable:

fn main() {
    let opt = Some(String::from("hi"));
    match opt {
        Some(ref s) => println!("{s} {}", s.len()),   // s is a &String
        None => {}
    }
    println!("{opt:?}");          // still usable: nothing was moved
}

Use ref mut to borrow mutably. Most code does not need either: matching on a reference (match &opt { Some(s) => ... } or if let Some(s) = &opt) borrows the same way, and since edition 2024 you may not write ref inside a pattern that already matches through a reference. Read ref when you meet it in older code; write & yourself.

Under the hood

  • Arrays are contiguous, like C. [T; N] has size N * size_of::<T>().
  • &[T] is two machine words: data pointer and length.
  • Layout is not guaranteed to match C. The compiler may reorder struct fields to reduce padding. To get the exact C layout use #[repr(C)] (chapter 21):
use std::mem::size_of;

#[allow(dead_code)]
struct Reordered { a: u8, b: u32, c: u8 }       // may be 8 bytes

#[allow(dead_code)]
#[repr(C)]
struct CLayout { a: u8, b: u32, c: u8 }         // 12 bytes, like the C struct

fn main() {
    println!("{} {}", size_of::<Reordered>(), size_of::<CLayout>());
}
  • An enum with data is a tag plus a payload sized for the largest variant. Where a type has an impossible value, the compiler hides the tag in it (a niche): for example Option<&T> is the same size as &T, with None stored as null. Chapter 14 builds on this.

C habits to unlearn

  • Do not pass (ptr, len) pairs; pass a slice.
  • Do not keep a kind field next to a union; use an enum.
  • Do not assume field order or padding unless the type is #[repr(C)].
  • Do not cast between an integer and an enum; use as to get the number and a match or TryFrom for the reverse.

Solutions

1.

fn largest(xs: &[i32]) -> Option<i32> {
    xs.iter().copied().max()
}

fn main() {
    println!("{:?} {:?}", largest(&[3, 9, 4]), largest(&[]));   // Some(9) None
}

A C function returning int has no value left over to mean “empty”: every int, including INT_MIN, may be a real maximum. C code uses a second return channel (an out-parameter plus a status code) or a sentinel that can collide with real data. Option<i32> keeps the two cases in the type, and the caller must handle both.

2. A new variant makes every match that omits it fail to compile:

#![allow(unused)]
fn main() {
enum Shape {
    Circle(f64),
    Rect(f64, f64),
    Triangle { base: f64, height: f64 },
}

fn area(s: &Shape) -> f64 {
    match s {                       // error[E0004]: non-exhaustive patterns: `&Shape::Triangle { .. }` not covered
        Shape::Circle(r) => 3.14159 * r * r,
        Shape::Rect(w, h) => w * h,
    }
}
}

Add Shape::Triangle { base, height } => 0.5 * base * height, and it compiles. In C, adding an enumerator is silent unless you remember to grep every switch.

3. Putting the two u8 fields next to each other removes the padding:

use std::mem::size_of;

#[allow(dead_code)]
#[repr(C)]
struct CLayout { a: u8, b: u32, c: u8 }      // 12 bytes

#[allow(dead_code)]
#[repr(C)]
struct Shrunk { a: u8, c: u8, b: u32 }       // 8 bytes

fn main() {
    println!("{} {}", size_of::<CLayout>(), size_of::<Shrunk>());   // 12 8
}

A plain Rust struct (without #[repr(C)]) is free to reorder fields and does this for you.

4.

use std::f64::consts::PI;

enum Shape {
    Circle(f64),
    Rect(f64, f64),
}

fn perimeter(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => 2.0 * PI * r,
        Shape::Rect(w, h) => 2.0 * (w + h),
    }
}

fn main() {
    assert_eq!(perimeter(&Shape::Rect(2.0, 3.0)), 10.0);
    assert!((perimeter(&Shape::Circle(1.0)) - 2.0 * PI).abs() < 1e-9);
    println!("ok");
}

5.

fn main() {
    let opt = Some(String::from("hi"));
    match opt {
        Some(ref s) => println!("{s}"),     // borrow with `ref`
        None => {}
    }
    println!("{opt:?}");

    match &opt {
        Some(s) => println!("{s}"),         // the modern spelling: match a reference
        None => {}
    }
    println!("{opt:?}");
}
