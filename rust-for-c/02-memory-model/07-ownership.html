Rust for C Programmers

Ownership and moves

In C

Heap memory has no owner in the language. By convention, someone must call free exactly once, and nobody may touch the memory afterwards. Nothing checks this.

char *a = malloc(6);
strcpy(a, "hello");
char *b = a;           /* two pointers, one block: who frees it? */
free(a);
free(b);               /* double free: undefined behavior */
printf("%s", a);       /* use after free: undefined behavior */

Most C bugs that become security holes are ownership mistakes: double free, use after free, leaks, and freeing the wrong pointer.

In Rust

Every value has exactly one owner: a variable. When the owner goes out of scope the value is dropped (freed). Assigning or passing a value to another variable moves ownership; the old name becomes unusable.

fn main() {
    let a = String::from("hello");   // a owns a heap buffer
    let b = a;                        // ownership moves to b
    println!("{b}");
}   // b goes out of scope: the buffer is freed, once

Using the old owner is a compile error, not a runtime bug:

fn main() {
    let a = String::from("hello");
    let b = a;
    println!("{a}");   // error[E0382]: borrow of moved value: `a`
    println!("{b}");
}

This one rule removes double free (only one owner frees), use after free (the old name is dead), and most leaks (the owner frees automatically).

Moves into and out of functions

fn consume(s: String) {
    println!("got {s}");
}   // s dropped here

fn pass_through(s: String) -> String {
    s                           // ownership returned to the caller
}

fn main() {
    let a = String::from("x");
    let a = pass_through(a);     // moved in, moved back out
    consume(a);                  // moved in for good
    // a is unusable here
}

Passing a value to a function is a move, just like assignment. To let a function look at a value without taking it, you borrow it (next chapter).

Cloning: an explicit deep copy

If you really want two independent owners, say so with .clone(). It is a visible allocation and copy, never silent:

fn main() {
    let a = String::from("hello");
    let b = a.clone();         // new heap buffer, same contents
    println!("{a} {b}");       // both valid
}

Copy types: plain data is copied, not moved

Types that are just bits (integers, floats, bool, char, tuples and arrays of those, shared references) implement Copy. They are copied on assignment, like in C, and the original stays usable.

fn main() {
    let x = 5;
    let y = x;               // copied
    println!("{x} {y}");     // both fine
}

A type that owns a resource (heap memory, a file) can never be Copy.

Partial moves and Box

Box<T> is the simplest owner: one heap allocation, like T *p = malloc(sizeof *p) with an automatic free.

fn main() {
    let b = Box::new(41);       // heap-allocated i32
    let c = *b + 1;             // dereference with *, like C
    println!("{c}");
}   // heap block freed here

Under the hood

  • A String is three words on the stack: a heap pointer, a length and a capacity. let b = a; copies those three words (a memcpy) and the compiler stops treating a as live. The heap bytes are not touched, so a move is cheap regardless of the string’s size.
 stack                       heap
 a: ptr ─┐  (dead after move)
 b: ptr ─┴──────────────▶  "hello"      one owner: b
  • There is no reference counting or garbage collector. The compiler inserts the free at the end of the owner’s scope. If a move happens on only some paths, it keeps a hidden “drop flag” so the value is still dropped exactly once.
  • A move is only a compile-time concept: the optimizer often removes the copy entirely.

C habits to unlearn

  • Do not write “the caller frees this” in a comment. The type already says who owns the value.
  • Do not copy pointers to share data. Move the value, borrow it, or clone() it deliberately.
  • Do not fear moves as slow. A move copies a few words, never the heap data.

Exercises

  1. Make the compile_fail example work in two different ways: by cloning, and by borrowing (let b = &a;).

  2. Write fn append_world(mut s: String) -> String that takes ownership, appends " world" with push_str, and returns it.

  3. Why does let t = (String::from("a"), 5); let u = t; make t unusable, but a (i32, i32) stays usable?

  4. Fix the code. consume takes ownership of the string, so name is gone afterwards. Fix it two ways: by cloning at the call, and by changing consume to borrow.

    fn consume(s: String) -> usize {
    s.len()
}

fn main() {
    let name = String::from("ferris");
    let n = consume(name);
    println!("{n} {name}");
}

  5. Write and test. Write fn longer(a: String, b: String) -> String that consumes both and returns the longer one (the first if they are equal). Explain why no clone is needed.

Solutions

1. Both fixes keep a usable:

fn main() {
    let a = String::from("hi");
    let b = a.clone();         // a deep copy: two owners of two buffers
    println!("{a} {b}");

    let c = String::from("yo");
    let d = &c;                // a borrow: one owner, one buffer
    println!("{c} {d}");
}

2.

fn append_world(mut s: String) -> String {
    s.push_str(" world");
    s
}

fn main() {
    let s = append_world(String::from("hello"));
    println!("{s}");   // hello world
}

3. A String owns a heap buffer, so copying the struct bytes would create two owners of one buffer (a double free in C). The tuple (String, i32) is therefore not Copy, and let u = t; moves it:

fn main() {
    let t = (String::from("a"), 5);
    let u = t;
    println!("{}", t.1);   // error[E0382]: borrow of moved value: `t`
}

(i32, i32) owns nothing, so a bitwise copy is complete. Such types implement Copy, and let u = t; leaves t usable.

4.

fn consume(s: String) -> usize {
    s.len()
}

fn borrow(s: &str) -> usize {
    s.len()
}

fn main() {
    let name = String::from("ferris");
    let a = consume(name.clone());     // fix 1: hand over a copy
    let b = borrow(&name);             // fix 2: lend instead of give
    println!("{a} {b} {name}");
}

Prefer fix 2 whenever the function only reads: no allocation, and name stays untouched.

5.

fn longer(a: String, b: String) -> String {
    if b.len() > a.len() { b } else { a }
}

fn main() {
    assert_eq!(longer("hi".to_string(), "hello".to_string()), "hello");
    assert_eq!(longer("ab".to_string(), "cd".to_string()), "ab");
    println!("ok");
}

Each argument is moved in, so the function owns both and may return either. The one not returned is dropped (freed) at the end of the function.
