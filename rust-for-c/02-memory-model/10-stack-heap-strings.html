Rust for C Programmers

Stack, heap, Box, Vec, String

In C

Locals live on the stack. Everything of dynamic size comes from malloc, and the size is yours to track. A string is a char * ending in a NUL byte, and its length is found by scanning.

int *v = malloc(n * sizeof *v);       /* you remember n */
v = realloc(v, 2 * n * sizeof *v);    /* may move; old pointers dangle */
char *s = malloc(6); strcpy(s, "hello");
size_t len = strlen(s);               /* O(n) scan for the NUL */
free(v); free(s);

In Rust

The same two regions exist, with owner types that do the bookkeeping:

Each owner frees its heap memory when it goes out of scope (chapter 11).

Box<T>

fn main() {
    let b = Box::new(5);        // a pointer to a heap i32
    println!("{}", *b + 1);     // 6
}                               // freed here

Use a Box for a single heap value, for a value too large for the stack, or for a recursive type (a linked list node needs a pointer to itself).

Vec<T>

A Vec<T> stores a pointer, a length and a capacity, the three variables a C program carries around by hand.

fn main() {
    let mut v = Vec::new();
    for i in 0..5 {
        v.push(i * i);                       // grows (reallocates) as needed
    }
    println!("{v:?} len={} cap>={}", v.len(), v.capacity());

    v[1] = 100;                              // indexing is bounds checked
    let total: i32 = v.iter().sum();
    println!("{total}");

    let first = v.first();                   // Option<&i32>
    println!("{first:?}");
    let v2 = vec![1, 2, 3];                  // the vec! macro, like an initializer
    println!("{}", v2.len());
}

A reference into the vector blocks push, so the realloc-invalidates-pointer bug of chapter 8 cannot happen.

String and &str

A String is an owned, growable UTF-8 buffer. A &str is a borrowed view of UTF-8 bytes (pointer + length). There is no NUL terminator; the length is stored, so len() is O(1) and strings may contain zero bytes.

fn greet(name: &str) -> String {        // takes a view, returns an owned string
    let mut out = String::from("hello, ");
    out.push_str(name);
    out.push('!');
    out
}

fn main() {
    let lit = "world";                  // &'static str, in the binary
    let owned = String::from("Rust");   // heap-allocated
    println!("{}", greet(lit));
    println!("{}", greet(&owned));      // &String converts to &str automatically
    println!("{}", lit.len());          // 5, no scan
}

Accept &str in function parameters; it takes both literals and &String.

Strings are UTF-8, so a character may be more than one byte. Indexing a string with an integer is not allowed, because “the nth byte” is rarely what you want:

fn main() {
    let s = String::from("héllo");
    let c = s[1];        // error[E0277]: the type `str` cannot be indexed by `{integer}`
}

Say what you mean instead:

fn main() {
    let s = String::from("héllo");
    println!("{}", s.len());                    // 6 bytes: é takes two
    println!("{}", s.chars().count());          // 5 characters
    println!("{:?}", s.chars().nth(1));         // Some('é')
    println!("{}", &s[0..1]);                   // "h": a byte range
    println!("{}", &s[1..3]);                   // "é"
    for b in s.bytes().take(3) {
        print!("{b} ");                         // 104 195 169
    }
    println!();
    // &s[0..2] would panic: byte 2 is in the middle of é.
}

For raw bytes with no encoding guarantees, use &[u8] / Vec<u8>.

Under the hood

 Vec<i32>: 3 words on the stack         heap
 ┌─────┬─────┬─────┐
 │ ptr │ len │ cap │ ───────────────▶ [ 0 | 1 | 4 | 9 | 16 | ...spare... ]
 └─────┴─────┴─────┘
  • Vec<T> and String are each currently three words (24 bytes on 64-bit); &str and &[T] are two words; Box<T> is one word for a sized T.
  • String is a Vec<u8> that the standard library keeps valid UTF-8.
  • Vec grows geometrically (about doubling), like a careful realloc loop, so push is amortized O(1). Use with_capacity when you know the size.
  • Heap memory comes from the system allocator by default (malloc on most platforms). You can replace it globally. It is the same allocator C code uses, so Rust and C can share it in FFI (chapter 21).
  • Stack arrays have fixed sizes known at compile time. Large ones can overflow the stack just as in C; put them in a Vec or Box.

C habits to unlearn

  • Do not track (pointer, length, capacity) separately; the types do it.
  • Do not use NUL termination. Use CString/CStr only at C boundaries.
  • Do not treat a string as an array of char. It is UTF-8 bytes; iterate chars() for code points.
  • Do not allocate just to pass text to a function. Take &str or &[T].

Solutions

1.

fn main() {
    let words: Vec<String> = vec!["one".into(), "two".into(), "three".into()];
    println!("{}", words.join(" "));   // one two three
}

2.

fn main() {
    let mut v: Vec<u8> = Vec::new();
    for i in 0..20 {
        v.push(i);
        print!("{} ", v.capacity());
    }
    println!();
}

With rustc 1.100 this prints 8 8 8 8 8 8 8 8 16 16 16 16 16 16 16 16 32 32 32 32: the first push allocates room for 8 bytes, then the capacity doubles when the buffer is full. This is the realloc doubling pattern you would write by hand in C. The exact numbers are an implementation detail and are not guaranteed.

3.

fn count_vowels(s: &str) -> usize {
    s.chars().filter(|c| "aeiouéèêàù".contains(*c)).count()
}

fn main() {
    println!("{}", count_vowels("café"));   // 2
}

chars() yields Unicode scalar values, so é is one item. A C loop over char sees the UTF-8 bytes 0xC3 0xA9 of é as two separate values, and neither equals 'e' or any other single-byte vowel, so it must decode UTF-8 itself.

4.

fn title_case(s: &str) -> String {
    s.split_whitespace()
        .map(|w| {
            let mut cs = w.chars();
            match cs.next() {
                Some(first) => first.to_uppercase().collect::<String>() + cs.as_str(),
                None => String::new(),
            }
        })
        .collect::<Vec<_>>()
        .join(" ")
}

fn main() {
    assert_eq!(title_case("hello big world"), "Hello Big World");
    assert_eq!(title_case(""), "");
    println!("ok");
}

5.

fn rle(s: &str) -> String {
    let mut out = String::new();
    let mut chars = s.chars().peekable();
    while let Some(c) = chars.next() {
        let mut n = 1;
        while chars.peek() == Some(&c) {
            chars.next();
            n += 1;
        }
        out.push(c);
        out.push_str(&n.to_string());
    }
    out
}

fn main() {
    assert_eq!(rle("aaabcc"), "a3b1c2");
    assert_eq!(rle(""), "");
    println!("ok");
}

String grows as needed, so there is no buffer size to compute and no snprintf to check.
