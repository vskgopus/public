Rust for C Programmers

Methods and associated functions

In C

There are no methods. The convention is a struct plus functions that take a pointer to it as the first argument, named with a prefix, and an init function that fills in a caller-provided struct.

struct stack { int *items; size_t len, cap; };

void stack_init(struct stack *s);
int  stack_push(struct stack *s, int x);
size_t stack_len(const struct stack *s);   /* const: read-only */
void stack_free(struct stack *s);

In Rust

An impl block attaches functions to a type. A function whose first parameter is self is a method, called with dot syntax. The kind of self says how it uses the value, which is exactly the const T * / T * / by-value distinction in C, checked by the compiler.

#[derive(Debug, Default)]
struct Stack {
    items: Vec<i32>,
}

impl Stack {
    const MAX: usize = 4;                       // associated constant

    fn new() -> Self {                          // associated function (a constructor)
        Self::default()
    }

    fn push(&mut self, x: i32) -> Result<(), i32> {
        if self.items.len() == Self::MAX {
            return Err(x);                      // full: hand the value back
        }
        self.items.push(x);
        Ok(())
    }

    fn pop(&mut self) -> Option<i32> {
        self.items.pop()
    }

    fn len(&self) -> usize {
        self.items.len()
    }

    fn into_vec(self) -> Vec<i32> {             // consumes the stack
        self.items
    }
}

fn main() {
    let mut s = Stack::new();                   // no stack_init, no out-pointer
    for i in 0..6 {
        if let Err(x) = s.push(i) {
            println!("full, rejected {x}");
        }
    }
    println!("{} {:?}", s.len(), s.pop());      // 4 Some(3)
    let v = s.into_vec();                       // s is moved
    println!("{v:?}");
}

Self means “the type this impl is for”. Stack::new() is not special; it is a plain function in the type’s namespace. There is no stack_free: the Vec inside is dropped with the struct (chapter 11).

The method call is sugar

s.len() is exactly Stack::len(&s). The compiler inserts the & or &mut (auto-reference), so you never write (&s)-> or (*p).:

struct Counter { n: u32 }
impl Counter {
    fn bump(&mut self) { self.n += 1; }
}

fn main() {
    let mut c = Counter { n: 0 };
    c.bump();                 // same as Counter::bump(&mut c)
    Counter::bump(&mut c);
    println!("{}", c.n);      // 2
}

A consuming method ends the value’s life:

struct Stack { items: Vec<i32> }
impl Stack {
    fn into_vec(self) -> Vec<i32> { self.items }
}

fn main() {
    let s = Stack { items: vec![1] };
    let v = s.into_vec();
    println!("{}", s.items.len());   // error[E0382]: borrow of moved value: `s`
    println!("{v:?}");
}

Several impl blocks and derive

A type may have any number of impl blocks. #[derive(...)] generates common implementations for you: Debug (printing with {:?}), Clone, Copy, PartialEq, Default, and others.

#[derive(Debug, Clone, Copy, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

impl Point {
    fn manhattan(&self) -> i32 {
        self.x.abs() + self.y.abs()
    }
}

fn main() {
    let a = Point { x: 3, y: -4 };
    let b = a;                         // Copy: `a` stays valid
    println!("{:?} {} {}", b, a == b, a.manhattan());
}

There is no inheritance. Types share behavior through traits (chapter 15), which cover the job of a C “ops table”.

Under the hood

  • Methods are ordinary functions. fn len(&self) compiles to a function taking a pointer, just like stack_len. There is no hidden vtable or per-object cost.
  • Calls are resolved at compile time and are easily inlined.
  • Self::default() and new do not allocate by themselves; Vec::new() does not allocate until the first push.

C habits to unlearn

  • Do not write init and free pairs. Write new, and let Drop clean up.
  • Do not use out-parameters for construction; return the value.
  • Choose the weakest self: &self by default, &mut self to modify, self only when consuming.

Solutions

1.

struct Stack { items: Vec<i32> }

impl Stack {
    fn peek(&self) -> Option<&i32> {
        self.items.last()
    }

    fn peek_copy(&self) -> Option<i32> {
        self.items.last().copied()
    }
}

fn main() {
    let mut s = Stack { items: vec![1, 2] };
    let top = s.peek_copy();   // an independent value
    s.items.push(3);           // fine
    println!("{top:?} {:?}", s.peek());
}

Option<&i32> avoids a copy and works for any element type, but the reference keeps the stack borrowed until you stop using it. Option<i32> (via .copied()) is independent of the stack, which is better for small Copy types. For large or non-Copy elements, return the reference.

2.

#[derive(Clone, Debug)]
struct Stack { items: Vec<i32> }

fn main() {
    let mut s = Stack { items: vec![1, 2] };
    let backup = s.clone();
    s.items.push(3);
    println!("{backup:?} {s:?}");
}

3.

struct Counter { n: u32 }

impl Counter {
    fn bump(&mut self) { self.n += 1; }
    fn reset(&mut self) { self.n = 0; }
}

fn main() {
    let mut c = Counter { n: 0 };
    c.bump();
    c.reset();                  // method call
    Counter::bump(&mut c);
    Counter::reset(&mut c);     // the same call, written as a plain function
    println!("{}", c.n);        // 0
}

4.

struct Account {
    balance: u32,
}

impl Account {
    fn deposit(&mut self, amount: u32) {
        self.balance += amount;
    }

    fn withdraw(&mut self, amount: u32) -> Result<(), String> {
        if amount > self.balance {
            return Err(format!("only {} available", self.balance));
        }
        self.balance -= amount;
        Ok(())
    }
}

fn main() {
    let mut a = Account { balance: 10 };
    a.deposit(5);
    assert_eq!(a.balance, 15);
    assert!(a.withdraw(20).is_err());
    assert_eq!(a.balance, 15);
    assert!(a.withdraw(15).is_ok());
    assert_eq!(a.balance, 0);
    println!("ok");
}

5.

#[derive(Debug, PartialEq)]
struct Config {
    port: u16,
    verbose: bool,
}

impl Config {
    fn new() -> Config {
        Config { port: 80, verbose: false }
    }

    fn port(mut self, p: u16) -> Config {
        self.port = p;
        self
    }

    fn verbose(mut self, v: bool) -> Config {
        self.verbose = v;
        self
    }
}

fn main() {
    let c = Config::new().port(8080).verbose(true);
    assert_eq!(c, Config { port: 8080, verbose: true });
    println!("ok");
}

Each method takes self by value and returns it, so the calls chain without borrowing.
