Rust for C Programmers

Traits and generics

In C

To write one function for many types, C offers void * plus a size and a function pointer, or preprocessor macros.

/* type-erased: no type checking, a call through a pointer per comparison */
void qsort(void *base, size_t n, size_t size,
           int (*cmp)(const void *, const void *));

/* macro: duplicated per use, no type check, double evaluation */
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int m = MAX(i++, j);       /* i++ may run twice */

In Rust

Generics write code once for many types, and the compiler checks it. Traits describe what a type can do, and generic code states which capabilities it needs (a bound).

A trait is a set of required functions

trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String {          // a default method, which types may override
        String::from("shape")
    }
}

struct Circle(f64);
struct Square(f64);

impl Shape for Circle {
    fn area(&self) -> f64 { 3.14159 * self.0 * self.0 }
    fn name(&self) -> String { String::from("circle") }
}

impl Shape for Square {
    fn area(&self) -> f64 { self.0 * self.0 }
}

fn print_area<T: Shape>(s: &T) {        // T must implement Shape
    println!("{} {}", s.name(), s.area());
}

fn main() {
    print_area(&Circle(1.0));
    print_area(&Square(2.0));
}

Generic functions with bounds

fn largest<T: PartialOrd + Copy>(xs: &[T]) -> T {
    let mut m = xs[0];
    for &x in xs {
        if x > m {
            m = x;
        }
    }
    m
}

fn main() {
    println!("{}", largest(&[3, 9, 2]));          // i32
    println!("{}", largest(&[1.5, 0.2]));         // f64
    println!("{}", largest(&['a', 'z', 'q']));    // char
}

T: PartialOrd + Copy reads “T can be compared with </> and copied”. Without the bound the body is rejected; the compiler will not let you call > on a type that may not have it:

#![allow(unused)]
fn main() {
fn largest<T>(a: T, b: T) -> T {
    if a > b { a } else { b }    // error[E0369]: binary operation `>` cannot be applied to type `T`
}
}

Long bounds go in a where clause:

use std::fmt::Display;

fn show_pair<A, B>(a: A, b: B) -> String
where
    A: Display,
    B: Display,
{
    format!("({a}, {b})")
}

fn main() {
    println!("{}", show_pair(1, "two"));
}

Generic types

struct Pair<T> {
    a: T,
    b: T,
}

impl<T: PartialOrd + Copy> Pair<T> {
    fn larger(&self) -> T {
        if self.a > self.b { self.a } else { self.b }
    }
}

fn main() {
    let p = Pair { a: 3, b: 8 };
    let q = Pair { a: 2.5, b: 1.0 };
    println!("{} {}", p.larger(), q.larger());
}

Vec<T>, Option<T> and Result<T, E> are ordinary generic types.

The newtype pattern and the orphan rule

You may implement a trait for a type only if your crate defines the trait or the type (the orphan rule). It stops two libraries from giving the same type conflicting behavior. When you need a foreign trait on a foreign type, wrap the type in a one-field tuple struct, a newtype, which is yours:

use std::fmt;

struct Names(Vec<String>);          // `Vec` and `Display` are both foreign; `Names` is ours

impl fmt::Display for Names {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}

fn main() {
    println!("{}", Names(vec!["ann".into(), "bob".into()]));   // [ann, bob]
}

A newtype costs nothing at run time: it has the same layout as the field inside. It is also how you give two u32 quantities (meters and seconds, say) different types so they cannot be mixed up, which a C typedef does not enforce.

Under the hood

  • Generics are monomorphized: for each concrete type used, the compiler generates a specialized copy of the function (largest::<i32>, largest::<f64>), as if you had written each by hand. There is no void *, no indirect call and no runtime type information, and every copy is fully optimized and inlinable.
  • The cost is code size and compile time, the same trade-off as C++ templates or macro-generated code, but type-checked once against the trait bound.
  • Trait methods on a concrete type are direct calls. For a call through a pointer, see dyn Trait in the next chapter.
  • Traits are open: you can implement your trait for someone else’s type, or someone else’s trait for your type, but not both foreign (the orphan rule).

C habits to unlearn

  • Do not erase types with void * to share code. Use generics.
  • Do not write macros to generate per-type functions. A generic function is checked, not text-pasted.
  • Do not add bounds you do not use; add exactly the ones the compiler asks for.

  5. Write and test. Use the newtype pattern: Meters(f64) and Seconds(f64). Implement std::ops::Div<Seconds> for Meters so that Meters(100.0) / Seconds(10.0) is 10.0. Check that swapping the arguments does not compile.

Solutions

1.

fn sum_all<T: std::ops::Add<Output = T> + Copy + Default>(xs: &[T]) -> T {
    let mut total = T::default();
    for &x in xs {
        total = total + x;
    }
    total
}

fn main() {
    println!("{} {}", sum_all(&[1, 2, 3]), sum_all(&[0.5, 1.5]));   // 6 2
}

The compiler generates one copy of sum_all for i32 and one for f64 (monomorphization), like two hand-written C functions.

2.

trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String;
}

struct Rect { w: f64, h: f64 }

impl Shape for Rect {
    fn area(&self) -> f64 { self.w * self.h }
    fn name(&self) -> String { String::from("rect") }
}

fn print_area<T: Shape>(s: &T) {
    println!("{} {}", s.name(), s.area());
}

fn main() {
    print_area(&Rect { w: 2.0, h: 3.0 });   // rect 6
}

3.

use std::fmt;

struct Point { x: i32, y: i32 }

impl fmt::Display for Point {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

fn main() {
    let p = Point { x: 1, y: 2 };
    println!("[{}]", p);       // [(1, 2)]
    println!("[{:>10}]", p);   // [(1, 2)]: the width is ignored
}

With write!, the width in {:>10} is ignored, because your fmt writes the pieces itself and never looks at the padding request. To honor it, build a String and pass it to f.pad(&s), which applies width, alignment and fill.

4.

fn largest<T: PartialOrd>(xs: &[T]) -> Option<&T> {
    let mut best = xs.first()?;
    for x in xs {
        if x > best {
            best = x;
        }
    }
    Some(best)
}

fn main() {
    assert_eq!(largest(&[3, 9, 4]), Some(&9));
    assert_eq!(largest(&["pear", "apple"]), Some(&"pear"));
    assert_eq!(largest::<i32>(&[]), None);
    println!("ok");
}

Returning a reference needs no Copy bound: the element stays in the slice.

5.

use std::ops::Div;

struct Meters(f64);
struct Seconds(f64);

impl Div<Seconds> for Meters {
    type Output = f64;                    // meters per second
    fn div(self, t: Seconds) -> f64 {
        self.0 / t.0
    }
}

fn main() {
    assert_eq!(Meters(100.0) / Seconds(10.0), 10.0);
    println!("ok");
}

Seconds(10.0) / Meters(100.0) is rejected, because no Div<Meters> for Seconds exists. Two C doubles would have accepted either order.
