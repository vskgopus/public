Rust for C Programmers

Modules and visibility

In C

Code is split into .c files, and the interface is in .h files that others #include. Everything is visible across files unless marked static. Include guards prevent double inclusion, and the linker resolves names.

/* stack.h */
#ifndef STACK_H
#define STACK_H
struct stack;                       /* opaque type */
struct stack *stack_new(void);
#endif

/* stack.c */
#include "stack.h"
static void helper(void) {}         /* file-private */

In Rust

A crate is a tree of modules. A module groups items and controls visibility. Everything is private by default; you opt in with pub. There are no header files, no include guards, and no separate declarations.

mod geometry {
    pub struct Point {
        pub x: i32,
        pub y: i32,
    }

    pub fn origin() -> Point {
        Point { x: 0, y: 0 }
    }

    fn helper() {}                      // private: like a `static` function

    pub mod shapes {
        use super::Point;               // `super` = the enclosing module

        pub fn dist2(a: &Point, b: &Point) -> i32 {
            (a.x - b.x).pow(2) + (a.y - b.y).pow(2)
        }
    }
}

use geometry::shapes::dist2;
use geometry::{origin, Point};

fn main() {
    let p = Point { x: 3, y: 4 };
    println!("{}", dist2(&p, &origin()));   // 25
}

Using a private item from outside is an error:

mod m {
    fn secret() {}
}

fn main() {
    m::secret();       // error[E0603]: function `secret` is private
}

Splitting across files

A module declaration with a semicolon tells the compiler to load the module from another file. The file layout mirrors the module tree:

src/
  main.rs            // crate root:   mod stack;  mod net;
  stack.rs           // module `stack`
  net/
    mod.rs           // module `net` (or net.rs next to the net/ folder)
    tcp.rs           // module `net::tcp`, declared with `mod tcp;` inside net

// main.rs
mod stack;                    // loads stack.rs
use stack::Stack;

fn main() {
    let mut s = Stack::new();
    s.push(1);
}

// stack.rs
pub struct Stack { items: Vec<i32> }      // field stays private
impl Stack {
    pub fn new() -> Stack { Stack { items: Vec::new() } }
    pub fn push(&mut self, x: i32) { self.items.push(x); }
}

Because items is private, code outside the module cannot touch it: a struct with private fields is an opaque type, the role struct stack; plus accessor functions plays in C, without a header.

use std::fmt::{self, Display};             // several names at once

    let m: Map<i32, i32> = Map::new();

}

Under the hood

  • Modules exist only at compile time. All items of a crate compile together, so the order of mod declarations and definitions is irrelevant, and calls across modules are inlined like any other.
  • Because the whole crate is one compilation unit, there are no duplicate-symbol or header-order problems.
  • Visibility is purely a compile-time check. It has no effect on the generated code, but it is what lets you keep invariants: if a field is private, only code in the module can break it.
  • Public symbol names are mangled (_ZN.../_R...) so modules cannot collide. Use #[unsafe(no_mangle)] pub extern "C" fn to export a C name (chapter 21).

C habits to unlearn

  • Do not duplicate a signature in a header; write it once.
  • Do not make everything pub. Start private and widen only as needed.
  • Do not use name prefixes; use modules.
  • Do not expose struct fields that carry invariants; give methods instead.

Exercises

  1. Split the geometry example into main.rs and geometry.rs on your machine.

  2. Call helper from shapes (it works: children can see their parent’s private items) and from main (it fails). Which visibility modifier fixes the second?

  3. Add pub use shapes::dist2; inside geometry and call geometry::dist2 from main.

  4. Fix the code. The field balance is private to the module, so main cannot touch it. Keep it private and add two public methods so the program compiles.

    mod bank {
    pub struct Account {
        balance: i64,
    }

    impl Account {
        pub fn new() -> Account {
            Account { balance: 0 }
        }
    }
}

fn main() {
    let mut a = bank::Account::new();
    a.balance = 100;
    assert_eq!(a.balance, 100);
}

  5. Write and test. Create mod stats { pub mod basic { pub fn mean(v: &[f64]) -> f64 } }, and re-export the function so callers write stats::mean(...).

Solutions

1. The crate root declares the module, and the module body moves to its own file:

src/main.rs        mod geometry;
                   use geometry::{origin, Point};
                   fn main() { /* ... */ }

src/geometry.rs    pub struct Point { pub x: i32, pub y: i32 }
                   pub fn origin() -> Point { Point { x: 0, y: 0 } }
                   pub mod shapes { /* ... */ }

2. Children see their ancestors’ private items, so helper works from shapes. The crate root is outside geometry, so the call is rejected until helper is pub (or pub(crate), which limits it to this crate):

mod geometry {
    fn helper() {}
    pub mod shapes {
        pub fn f() { super::helper(); }   // fine: a child sees its parent's private items
    }
}

fn main() {
    geometry::helper();   // error[E0603]: function `helper` is private
}

3.

mod geometry {
    pub mod shapes {
        pub fn dist2(a: i32, b: i32) -> i32 { (a - b).pow(2) }
    }
    pub use shapes::dist2;   // re-export: geometry::dist2 now exists
}

fn main() {
    println!("{}", geometry::dist2(5, 2));   // 9
}

4.

mod bank {
    pub struct Account {
        balance: i64,
    }

    impl Account {
        pub fn new() -> Account {
            Account { balance: 0 }
        }

        pub fn deposit(&mut self, amount: i64) {
            self.balance += amount;
        }

        pub fn balance(&self) -> i64 {
            self.balance
        }
    }
}

fn main() {
    let mut a = bank::Account::new();
    a.deposit(100);
    assert_eq!(a.balance(), 100);
    println!("ok");
}

This is the opaque-struct idiom of C (struct account; in the header, functions in the .c file), enforced by the compiler.

5.

mod stats {
    pub mod basic {
        pub fn mean(v: &[f64]) -> f64 {
            v.iter().sum::<f64>() / v.len() as f64
        }
    }
    pub use basic::mean;           // re-export at the shorter path
}

fn main() {
    assert_eq!(stats::mean(&[1.0, 2.0, 3.0]), 2.0);
    assert_eq!(stats::basic::mean(&[2.0, 4.0]), 3.0);   // the long path still works
    println!("ok");
}
