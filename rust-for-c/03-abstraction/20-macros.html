Rust for C Programmers

Macros

In C

The preprocessor rewrites text before the compiler sees it. It has no idea about types, scopes or expression boundaries, which produces classic bugs.

#define SQUARE(x) x * x
int a = SQUARE(1 + 2);          /* 1 + 2 * 1 + 2 == 5, not 9 */

#define SWAP(a, b) { int tmp = a; a = b; b = tmp; }
int tmp = 1, y = 2;
SWAP(tmp, y);                   /* expands to int tmp = tmp; ... : wrong */

#define MAX(a, b) ((a) > (b) ? (a) : (b))
int m = MAX(i++, j);            /* i++ may be evaluated twice */

In Rust

A Rust macro works on the syntax tree, not on text. Macros are invoked with a !, like println!, vec!, assert_eq!. You will use the standard ones every day and write your own rarely.

fn main() {
    let v = vec![1, 2, 3];                       // builds a Vec
    assert_eq!(v.len(), 3);                      // checks, prints both sides on failure
    println!("{} {:?}", v.len(), v);             // formatting checked at compile time
}

println!("{}") with a missing argument is a compile error, where printf is silent undefined behavior:

fn main() {
    println!("{} {}", 1);     // error: 2 positional arguments in format string, but there is 1 argument
}

Declarative macros: macro_rules!

A macro is a set of patterns that match the tokens at the call site and produce code. Fragment types such as expr, ident and ty say what each part must be.

macro_rules! square {
    ($x:expr) => {{
        let v = $x;                  // evaluate the argument once
        v * v
    }};
}

fn main() {
    println!("{}", square!(1 + 2));  // 9: the argument is one expression, not loose text
}

Unlike C, $x is a whole expression node, so 1 + 2 is not re-associated. Hygiene also keeps the macro’s own v from clashing with the caller’s variables, which solves the SWAP(tmp, y) bug:

macro_rules! swap {
    ($a:ident, $b:ident) => {
        let tmp = $a;                // this `tmp` is invisible to the caller
        $a = $b;
        $b = tmp;
    };
}

fn main() {
    let mut tmp = 1;
    let mut y = 2;
    swap!(tmp, y);                   // works even though the caller also has `tmp`
    println!("{tmp} {y}");           // 2 1
}

Macros can take a variable number of arguments with repetition $( ... ),* and can call themselves:

macro_rules! max {
    ($x:expr) => ($x);
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = max!($($rest),+);
        if a > b { a } else { b }
    }};
}

fn main() {
    println!("{}", max!(3, 9, 4));   // 9
}

Note that the macro pastes the argument’s code in for every $x it mentions, which is why square first binds let v = $x;.

Other kinds of macros

  • Derive macros (#[derive(Debug, Clone)]) generate trait implementations.
  • Attribute macros (#[test], #[tokio::main]) transform an item.
  • Procedural macros are Rust programs that run at compile time on the token stream. They are written in their own crate. They replace code generators and X-macros.

Under the hood

  • Macro expansion happens after parsing: the output must be valid syntax, and the result is type-checked like handwritten code.
  • Use cargo expand (a separate tool) or rustc -Zunpretty=expanded (nightly) to view the expansion, the equivalent of gcc -E.
  • Errors inside a macro point at the call site and the macro definition, which can be hard to read: keep macros small.

C habits to unlearn

  • Do not use a macro where a const, a function or a generic will do.
  • Do not wrap every argument in parentheses; Rust macros do not need that.
  • Do not write a macro just to pass a type; use generics.
  • Write macros last, and keep them small and well tested.

Exercises

  1. Write macro_rules! min like max.

  2. Write a macro hashmap!{ "a" => 1, "b" => 2 } that builds a HashMap.

  3. Run println!("{}", 1) with an extra argument and read the compile error.

  4. Fix the macro. square! is wrong on purpose: it returns its argument. Fix it so both checks pass, and evaluate the argument only once.

    macro_rules! square {
    ($x:expr) => {
        $x
    };
}

fn main() {
    assert_eq!(square!(3), 9);
    assert_eq!(square!(1 + 2), 9);
    println!("ok");
}

  5. Write and test. Write my_vec![1, 2, 3] (with an optional trailing comma) that builds a Vec.

Solutions

1.

macro_rules! min {
    ($x:expr) => ($x);
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = min!($($rest),+);
        if a < b { a } else { b }
    }};
}

fn main() {
    println!("{}", min!(3, 9, 4));   // 3
}

2.

use std::collections::HashMap;

macro_rules! hashmap {
    ($($k:expr => $v:expr),* $(,)?) => {{
        let mut m = HashMap::new();
        $( m.insert($k, $v); )*
        m
    }};
}

fn main() {
    let m = hashmap!{ "a" => 1, "b" => 2 };
    println!("{}", m["a"] + m["b"]);   // 3
}

3. The format string is checked at compile time, which printf cannot do:

fn main() {
    println!("{}", 1, 2);   // error: argument never used
}

4.

macro_rules! square {
    ($x:expr) => {{
        let v = $x;
        v * v
    }};
}

fn main() {
    assert_eq!(square!(3), 9);
    assert_eq!(square!(1 + 2), 9);
    println!("ok");
}

An expr fragment keeps its grouping, so square!(1 + 2) is 3 * 3, not 1 + 2 * 1 + 2 as the C macro #define SQ(x) x * x gives. The let evaluates the argument only once.

5.

macro_rules! my_vec {
    ($($x:expr),* $(,)?) => {{
        let mut v = Vec::new();
        $( v.push($x); )*
        v
    }};
}

fn main() {
    let a = my_vec![1, 2, 3];
    let b: Vec<i32> = my_vec![];
    let c = my_vec![4, 5,];
    assert_eq!(a, [1, 2, 3]);
    assert!(b.is_empty());
    assert_eq!(c, [4, 5]);
    println!("ok");
}
