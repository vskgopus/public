Rust for C Programmers

FFI: calling C from Rust and Rust from C

In C

Linking two C translation units needs only matching declarations. Types, layout and calling convention are the platform’s, and the linker joins symbols by name.

/* util.h */
int util_add(int a, int b);
/* main.c */
#include "util.h"
int main(void) { return util_add(1, 2); }

In Rust

Rust has its own unstable ABI and layout, so crossing into C requires saying so explicitly: extern "C" for the calling convention, #[repr(C)] for the layout, and unsafe because the compiler cannot check what is on the other side.

Calling C from Rust

Declare the foreign functions in an unsafe extern "C" block. The C library is already linked into every Rust program on most platforms, so this runs as is:

use std::ffi::{c_char, c_int, CString};

unsafe extern "C" {
    fn abs(x: c_int) -> c_int;
    fn strlen(s: *const c_char) -> usize;
}

fn main() {
    let s = CString::new("hello").unwrap();   // NUL-terminated copy
    unsafe {
        println!("{}", abs(-5));              // 5
        println!("{}", strlen(s.as_ptr()));   // 5
    }
}

Every call is unsafe: the compiler trusts your declaration. A wrong signature is undefined behavior, as in C with a mismatched prototype. To link your own C library, add #[link(name = "foo")] on the block or a build.rs that compiles it (the cc crate does this).

Option<&T> and Option<extern "C" fn(...)> have the same representation as a nullable pointer, so they are the right type for “may be NULL”.

Strings across the boundary

Rust strings are not NUL-terminated and may contain zero bytes; C strings are the opposite. Use CString (owned, adds the NUL) to hand text to C and CStr (borrowed) to read text from C:

use std::ffi::{c_char, CStr, CString};

fn main() {
    let owned = CString::new("hi").unwrap();
    let p: *const c_char = owned.as_ptr();           // valid while `owned` lives
    let back: &CStr = unsafe { CStr::from_ptr(p) };  // a view of the C string
    println!("{}", back.to_str().unwrap());          // hi
    // CString::new("a\0b") would return Err: interior NUL
}

Do not keep as_ptr() of a temporary: CString::new("x").unwrap().as_ptr() dangles at the end of the statement.

Layout: #[repr(C)]

use std::mem::{align_of, size_of};

#[repr(C)]
struct Header {      // identical layout to: struct header { uint8_t kind; uint32_t len; uint8_t flag; };
    kind: u8,
    len: u32,
    flag: u8,
}

fn main() {
    println!("{} {}", size_of::<Header>(), align_of::<Header>());  // 12 4
}

Without repr(C) Rust may reorder fields. Other layout attributes: #[repr(u8)] (enum with a fixed integer size), #[repr(transparent)] (a wrapper with exactly the layout of its one field), #[repr(packed)] (no padding, and taking references to its fields is a hazard).

Callbacks: passing Rust functions to C

An extern "C" fn is a plain C function pointer. This calls the C library’s qsort:

use std::ffi::c_void;

unsafe extern "C" {
    fn qsort(
        base: *mut c_void,
        n: usize,
        size: usize,
        cmp: extern "C" fn(*const c_void, *const c_void) -> i32,
    );
}

extern "C" fn cmp_i32(a: *const c_void, b: *const c_void) -> i32 {
    let (a, b) = unsafe { (*(a as *const i32), *(b as *const i32)) };
    a.cmp(&b) as i32                       // Ordering is -1, 0, 1
}

fn main() {
    let mut v = [5, 2, 9, 1];
    unsafe {
        qsort(v.as_mut_ptr() as *mut c_void, v.len(), size_of::<i32>(), cmp_i32);
    }
    println!("{v:?}");                     // [1, 2, 5, 9]
}

A closure cannot be passed directly: C has nowhere to put its captured state. Use the usual C pattern, a void *ctx parameter pointing at your data.

Calling Rust from C

Export a function with an unmangled name and the C ABI, and build the crate as a static or dynamic library:

// src/lib.rs
#[unsafe(no_mangle)]
pub extern "C" fn rs_add(a: i32, b: i32) -> i32 {
    a + b
}
# Cargo.toml
[lib]
crate-type = ["staticlib", "cdylib"]    # .a and .so/.dll

/* main.c, linked with libmycrate.a */
int rs_add(int a, int b);
int main(void) { return rs_add(1, 2); }

The tool cbindgen generates the C header from your Rust, and bindgen generates Rust declarations from a C header, so neither side is written twice.

A panic must not unwind into C. An extern "C" function aborts the process if a panic escapes it. Catch errors and return a status code (or use catch_unwind).

Ownership across the boundary

Hand a heap value to C as a raw pointer and take it back later with the matching function. Never free Rust memory with free, or C memory with Rust’s drop; each side must release with its own allocator:

pub struct Counter { n: u32 }

#[unsafe(no_mangle)]
pub extern "C" fn counter_new() -> *mut Counter {
    Box::into_raw(Box::new(Counter { n: 0 }))     // ownership leaves Rust
}

#[unsafe(no_mangle)]
pub extern "C" fn counter_bump(c: *mut Counter) -> u32 {
    let c = unsafe { c.as_mut() }.expect("null counter");
    c.n += 1;
    c.n
}

#[unsafe(no_mangle)]
pub extern "C" fn counter_free(c: *mut Counter) {
    if !c.is_null() {
        drop(unsafe { Box::from_raw(c) });           // ownership returns, then freed
    }
}

This is the opaque-handle pattern from C, with the allocation and the free defined together.

Under the hood

  • extern "C" selects the platform C calling convention (System V AMD64, AAPCS, Windows x64, …). Calls are ordinary calls, with no marshalling or runtime cost.
  • #[unsafe(no_mangle)] keeps the symbol name exactly rs_add instead of Rust’s mangled name. In edition 2024 the attribute must be wrapped in unsafe(...).
  • Rust and C can share one allocator (malloc) in practice, but treat the two as separate: free with the side that allocated.
  • Link order and libraries are handled by Cargo; static libraries from Rust bundle the Rust runtime pieces they need.

C habits to unlearn

  • Do not cast away types to cross the boundary; declare them precisely.
  • Do not let C own a Rust Box or Rust own a malloc block without a matching free function.
  • Keep the FFI surface tiny and wrap it in a safe Rust API once.
  • Do not assume char is signed or long is 64 bits: use c_char, c_long.

Solutions

1.

use std::ffi::{c_char, c_int, CString};

unsafe extern "C" {
    fn getpid() -> c_int;
    fn atoi(s: *const c_char) -> c_int;
}

fn main() {
    let s = CString::new("1234").unwrap();
    // SAFETY: `s` is a valid NUL-terminated string that outlives the call.
    let (pid, n) = unsafe { (getpid(), atoi(s.as_ptr())) };
    println!("{} {n}", pid > 0);   // true 1234
}

2.

use std::mem::size_of;

#[repr(C)]
struct Point { x: i32, y: i32 }

fn main() {
    println!("{}", size_of::<Point>());   // 8, the same as C's sizeof(struct { int32_t x, y; })
}

3. The signature returns a Result, because a plain usize has no way to report an error:

use std::ffi::{c_char, CString, NulError};

unsafe extern "C" {
    fn strlen(s: *const c_char) -> usize;
}

fn c_strlen(s: &str) -> Result<usize, NulError> {
    let c = CString::new(s)?;                // Err if `s` contains a NUL byte
    // SAFETY: `c` is NUL-terminated and valid for the call.
    Ok(unsafe { strlen(c.as_ptr()) })
}

fn main() {
    println!("{:?}", c_strlen("hello"));   // Ok(5)
    println!("{:?}", c_strlen("he\0llo")); // Err(NulError(2, ...))
}

4.

unsafe extern "C" {
    fn abs(x: i32) -> i32;
}

fn c_abs(x: i32) -> i32 {
    // SAFETY: `abs` has no preconditions beyond a valid int.
    unsafe { abs(x) }
}

fn main() {
    assert_eq!(c_abs(-5), 5);
    assert_eq!(c_abs(7), 7);
    println!("ok");
}

The wrapper hides the unsafe from callers. (i32::abs is the safe, idiomatic call; this is practice for functions that have no Rust version.)

5.

use std::mem::{offset_of, size_of};

#[repr(C)]
struct Header {
    a: u8,
    b: u32,
    c: u16,
}

fn main() {
    assert_eq!(offset_of!(Header, a), 0);
    assert_eq!(offset_of!(Header, b), 4);    // 3 bytes of padding after `a`
    assert_eq!(offset_of!(Header, c), 8);
    assert_eq!(size_of::<Header>(), 12);     // 2 bytes of tail padding, for alignment 4
    println!("ok");
}

These numbers are exactly what a C compiler gives for the same struct on common targets.
