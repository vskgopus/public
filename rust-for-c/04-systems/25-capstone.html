Rust for C Programmers

Capstone: porting a C project

This chapter ports two small C programs step by step, using only what the earlier chapters introduced:

  1. a singly linked list of int,
  2. a word-frequency tool, which in C needs a hand-written hash table.

The complete, tested Rust code for both is listed at the end of each part. To follow along, create a library crate with cargo new --lib list and add each step to src/lib.rs.

This chapter does not use the usual six-section template: each part walks through a port step by step, and Part 1 ends with a side-by-side table.

Part 1: the linked list

The C version

struct node { int val; struct node *next; };
struct list { struct node *head; size_t len; };

void list_init(struct list *l);
int  list_push(struct list *l, int val);          /* -1 on malloc failure */
int  list_pop(struct list *l, int *out);          /* -1 if empty */
void list_reverse(struct list *l);
void list_free(struct list *l);                   /* caller must remember */

Review the hazards before porting: malloc can fail and the caller must check; pop uses an out-parameter and a sentinel return; nothing stops using the list after list_free; and forgetting list_free leaks.

Step 1: data layout (chapters 6, 10, 14)

A next pointer that may be NULL is Option; an owned heap node is Box:

type Link = Option<Box<Node>>;

struct Node {
    val: i32,
    next: Link,
}

pub struct List {
    head: Link,
    len: usize,
}

Option<Box<Node>> is the same size as a pointer (chapter 14), so the layout is the same as the C struct. There is no malloc failure to check: allocation failure aborts the process, which is the usual choice outside embedded code.

Step 2: construction and push (chapters 7, 13)

impl List {
    pub fn new() -> Self {
        List { head: None, len: 0 }
    }

    pub fn push(&mut self, val: i32) {
        let node = Box::new(Node { val, next: self.head.take() });
        self.head = Some(node);
        self.len += 1;
    }
}

list_init becomes new. push cannot fail, so it returns nothing. The key operation is self.head.take(): it moves the old head out and leaves None behind. In C you would write n->next = l->head; and briefly have two pointers to the same node. Rust does not allow two owners, so take() makes the hand-over explicit.

Step 3: pop and peek (chapters 8, 14)

pub fn pop(&mut self) -> Option<i32> {
    self.head.take().map(|n| {
        self.head = n.next;       // move the rest of the list up
        self.len -= 1;
        n.val
    })                            // the node's Box is freed here
}

pub fn peek(&self) -> Option<&i32> {
    self.head.as_ref().map(|n| &n.val)
}

The out-parameter and -1 are gone: Option<i32> says “a value or nothing”. free(n) is gone too, because the Box is dropped at the end of the closure. peek returns a reference tied to &self (chapter 9), so the list cannot be modified while the reference is alive.

Step 4: reverse (chapters 5, 7)

pub fn reverse(&mut self) {
    let mut prev: Link = None;
    let mut cur = self.head.take();
    while let Some(mut n) = cur {
        cur = n.next.take();      // C: next = cur->next
        n.next = prev;            // C: cur->next = prev
        prev = Some(n);           // C: prev = cur
    }
    self.head = prev;
}

It is line for line the C algorithm, with each pointer assignment written as a move. Ownership of every node passes from cur to prev exactly once, so no node is lost or freed twice.

Step 5: iteration (chapters 9, 18)

A C caller walks for (n = l->head; n; n = n->next) and can break the list while doing it. The Rust version is an iterator that borrows the list:

pub struct Iter<'a> {
    next: Option<&'a Node>,
}

impl<'a> Iterator for Iter<'a> {
    type Item = &'a i32;

    fn next(&mut self) -> Option<&'a i32> {
        self.next.map(|n| {
            self.next = n.next.as_deref();
            &n.val
        })
    }
}

impl List {
    pub fn iter(&self) -> Iter<'_> {
        Iter { next: self.head.as_deref() }
    }
}

With that, sum, max, collect, filter and the rest of chapter 18 work on your list for free.

Step 6: Drop replaces list_free (chapter 11)

The compiler writes the drop code for Box and Option automatically, but it is recursive: dropping a node drops its next, and so on. A list of a million nodes would overflow the stack. This is the classic pitfall when porting a C list. Write the loop yourself:

impl Drop for List {
    fn drop(&mut self) {
        let mut cur = self.head.take();
        while let Some(mut n) = cur {
            cur = n.next.take();      // detach, so each node drops with no children
        }
    }
}

Now list_free cannot be forgotten or called twice, and use after free cannot compile.

Step 7: tests (chapter 24)

#[test]
fn reverse_and_iter() {
    let mut l = List::new();
    for i in 1..=3 {
        l.push(i);
    }
    assert_eq!(l.iter().copied().collect::<Vec<_>>(), [3, 2, 1]);
    l.reverse();
    assert_eq!(l.iter().sum::<i32>(), 6);
}

The complete list

The C original:

#include <stdio.h>
#include <stdlib.h>

struct node {
    int val;
    struct node *next;
};

struct list {
    struct node *head;
    size_t len;
};

static void list_init(struct list *l) { l->head = NULL; l->len = 0; }

static int list_push(struct list *l, int val) {
    struct node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->val = val;
    n->next = l->head;
    l->head = n;
    l->len++;
    return 0;
}

/* returns 0 and stores the value, or -1 if empty */
static int list_pop(struct list *l, int *out) {
    struct node *n = l->head;
    if (!n) return -1;
    *out = n->val;
    l->head = n->next;
    free(n);
    l->len--;
    return 0;
}

static void list_reverse(struct list *l) {
    struct node *prev = NULL, *cur = l->head;
    while (cur) {
        struct node *next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    l->head = prev;
}

static void list_free(struct list *l) {
    int dummy;
    while (list_pop(l, &dummy) == 0) {}
}

int main(void) {
    struct list l;
    list_init(&l);
    for (int i = 1; i <= 3; i++)
        if (list_push(&l, i) != 0) return 1;
    list_reverse(&l);
    int v;
    while (list_pop(&l, &v) == 0) printf("%d ", v);
    printf("\n");
    list_free(&l);
    return 0;
}

The Rust port, with its tests:

//! Singly linked list of i32: the Rust port of the C list in chapter 25.

type Link = Option<Box<Node>>;

struct Node {
    val: i32,
    next: Link,
}

#[derive(Default)]
pub struct List {
    head: Link,
    len: usize,
}

impl List {
    pub fn new() -> Self {
        Self::default()
    }

    pub fn len(&self) -> usize {
        self.len
    }

    pub fn is_empty(&self) -> bool {
        self.head.is_none()
    }

    pub fn push(&mut self, val: i32) {
        let node = Box::new(Node { val, next: self.head.take() });
        self.head = Some(node);
        self.len += 1;
    }

    pub fn pop(&mut self) -> Option<i32> {
        self.head.take().map(|n| {
            self.head = n.next;
            self.len -= 1;
            n.val
        })
    }

    pub fn peek(&self) -> Option<&i32> {
        self.head.as_ref().map(|n| &n.val)
    }

    pub fn reverse(&mut self) {
        let mut prev: Link = None;
        let mut cur = self.head.take();
        while let Some(mut n) = cur {
            cur = n.next.take();
            n.next = prev;
            prev = Some(n);
        }
        self.head = prev;
    }

    pub fn iter(&self) -> Iter<'_> {
        Iter { next: self.head.as_deref() }
    }
}

pub struct Iter<'a> {
    next: Option<&'a Node>,
}

impl<'a> Iterator for Iter<'a> {
    type Item = &'a i32;

    fn next(&mut self) -> Option<&'a i32> {
        self.next.map(|n| {
            self.next = n.next.as_deref();
            &n.val
        })
    }
}

impl Drop for List {
    // Iterative drop: the default recursive drop would overflow the stack on a long list.
    fn drop(&mut self) {
        let mut cur = self.head.take();
        while let Some(mut n) = cur {
            cur = n.next.take();
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn push_pop_peek() {
        let mut l = List::new();
        assert_eq!(l.pop(), None);
        l.push(1);
        l.push(2);
        assert_eq!(l.peek(), Some(&2));
        assert_eq!(l.pop(), Some(2));
        assert_eq!(l.len(), 1);
    }

    #[test]
    fn reverse_and_iter() {
        let mut l = List::new();
        for i in 1..=3 {
            l.push(i);
        }
        assert_eq!(l.iter().copied().collect::<Vec<_>>(), [3, 2, 1]);
        l.reverse();
        assert_eq!(l.iter().sum::<i32>(), 6);
        assert_eq!(l.iter().copied().collect::<Vec<_>>(), [1, 2, 3]);
    }

    #[test]
    fn long_list_drops_without_overflow() {
        let mut l = List::new();
        for i in 0..1_000_000 {
            l.push(i);
        }
        assert_eq!(l.len(), 1_000_000);
    }
}

Part 2: the word-frequency tool

In C this needs a hash function, a table with collision handling, resizing, and string ownership: often 150 lines and several memory bugs. In Rust the standard library does it:

use std::collections::HashMap;
use std::io::{self, BufRead};

fn main() -> io::Result<()> {
    let mut counts: HashMap<String, usize> = HashMap::new();
    for line in io::stdin().lock().lines() {
        let line = line?;
        for w in line.split_whitespace() {
            *counts.entry(w.to_lowercase()).or_insert(0) += 1;
        }
    }
    let mut items: Vec<(String, usize)> = counts.into_iter().collect();
    items.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(&b.0)));   // count desc, then word
    for (w, n) in items.iter().take(10) {
        println!("{n:>6} {w}");
    }
    Ok(())
}

Put it in src/main.rs of a binary crate and run it as cargo run < somefile.txt. (Run on the Playground, it reads an empty input and prints nothing.) This uses almost every earlier chapter: HashMap and iterators (18), closures (17), String and &str (10), Result and ? (14), main returning an error (14), and tuples (6). There is no unsafe, no free and no buffer-length bookkeeping.

Solutions

1. A singly linked list with only a head pointer must walk to the end to append, which is O(n):

struct Node { val: i32, next: Option<Box<Node>> }

struct List { head: Option<Box<Node>> }

impl List {
    fn push_back(&mut self, val: i32) {
        let mut cur = &mut self.head;
        while let Some(node) = cur {
            cur = &mut node.next;
        }
        *cur = Some(Box::new(Node { val, next: None }));
    }
}

fn main() {
    let mut l = List { head: None };
    l.push_back(1);
    l.push_back(2);
    println!("{}", l.head.as_ref().unwrap().next.as_ref().unwrap().val);   // 2
}

A C list keeps a tail pointer to make push_back O(1). In Rust that pointer would be a second owner of the last node, which Box forbids. Your options are unsafe raw pointers (and the proofs that go with them), Rc<RefCell<Node>> (shared ownership with run-time checks), or a different structure such as VecDeque, which already solves this.

2.

struct Node<T> { val: T, next: Option<Box<Node<T>>> }

struct List<T> { head: Option<Box<Node<T>>> }

impl<T> List<T> {
    fn new() -> Self { List { head: None } }

    fn push(&mut self, val: T) {
        let node = Box::new(Node { val, next: self.head.take() });
        self.head = Some(node);
    }

    fn pop(&mut self) -> Option<T> {
        self.head.take().map(|n| {
            self.head = n.next;
            n.val
        })
    }
}

fn main() {
    let mut l = List::new();
    l.push("a");
    l.push("b");
    println!("{:?} {:?}", l.pop(), l.pop());   // Some("b") Some("a")
}

Add <T> to the structs and the impl, and replace i32 with T. The C version needed void * and a size or a macro-generated copy per type.

3. Read the first argument and fall back to 10 on a missing or invalid value:

fn top_n() -> usize {
    std::env::args().nth(1).and_then(|a| a.parse().ok()).unwrap_or(10)
}

fn main() {
    let items = ["a", "b", "c"];
    for w in items.iter().take(top_n()) {
        println!("{w}");
    }
}

In wordfreq, replace .take(10) with .take(top_n()).

4. Open-ended. A useful method: run the C function on a table of inputs and write the results down as test cases first. Then port the function and make the tests pass in Rust. For a tokenizer, strtok modifies its input and keeps hidden global state, while str::split returns an iterator and leaves the input alone:

fn tokens<'a>(s: &'a str, delims: &[char]) -> Vec<&'a str> {
    s.split(|c| delims.contains(&c)).filter(|t| !t.is_empty()).collect()
}

fn main() {
    assert_eq!(tokens("a,b;;c", &[',', ';']), ["a", "b", "c"]);
}

5.

struct Node {
    val: i32,
    next: Option<Box<Node>>,
}

struct List {
    head: Option<Box<Node>>,
}

impl List {
    fn push(&mut self, val: i32) {
        let node = Box::new(Node { val, next: self.head.take() });
        self.head = Some(node);
    }

    fn contains(&self, x: i32) -> bool {
        let mut cur = self.head.as_deref();
        while let Some(node) = cur {
            if node.val == x {
                return true;
            }
            cur = node.next.as_deref();
        }
        false
    }
}

fn main() {
    let mut l = List { head: None };
    l.push(1);
    l.push(2);
    assert!(l.contains(1));
    assert!(!l.contains(9));
    println!("ok");
}

as_deref() turns &Option<Box<Node>> into Option<&Node>: a borrowed cursor with no raw pointers, like the C loop for (n = head; n; n = n->next).
